Núcleo freestanding para AArch64 — sem libc, sem includes. Implementa um ciclo de estados com BitStack append-only e CRC32 bitwise. Roda em QEMU virt ou bare-metal.

G · Modelo Conceitual

BitStack World Model — SPEC.md

Ontologia formal que define como matéria, leis e memória se comportam no sistema. Base conceitual do rf_core e da validação por blocos.

  • MatériaNibbles e bytes como substrato físico-lógico. Quando organizados formam blocos; blocos formam mundos. A matéria é o único substrato real — tudo o mais é organização sobre ela.
  • Leis (Witness)Regras de validação por bloco. Um bloco só é utilizável quando sua verificação retorna Witness=true. Blocos inválidos são preservados mas não consumidos.
  • MemóriaBase imutável + overlays/layers equivalentes. Todos os layers seguem o mesmo esquema de blocos. A base nunca é sobrescrita — apenas lida.
  • TestemunhaProcesso explícito que percorre cada bloco e estampa Witness=true ou false. Análogo a um commit: só o que foi testemunhado entra no fluxo canônico.

Analogia operacional: o ciclo ψ→Ω do rf_core implementa este modelo — ψ é o reset ao estado "matéria limpa", Ω é a saída testemunhada.

I · Motor de Simulação

Triad Engine — TRIAD / TEXTURE10 / toro

Simulação de dinâmica de campo sobre estrutura toroidal. Produz os traços CSV consumidos pelo GBS Console. Acoplado ao corpus CTI via triad_cti_couple.py.

run.sh→ src/triad_engine.py --steps 300 --seed 42 →out/triad_trace.csv
triad_cti_couple.py→ acopla CTI a toro / TRIAD / TEXTURE10 / love_guard

O parâmetro --seed garante determinismo total — a mesma semente com os mesmos dados produz o mesmo traço, permitindo reprodutibilidade.
