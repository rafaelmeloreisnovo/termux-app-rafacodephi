A · Ingestão de Dados

CTI Scan — Pipeline de Entrada

Converte exportações de conversas (ChatGPT/Claude) em artefatos JSONL estruturados para busca e análise. Entrada: ZIP ou JSON raw de exportação. Saída: omega_msgs.jsonl — índice central de busca para todos os processos posteriores.

conversations.json → omega_json_reconstruct → omega_objs.jsonl → omega_extract_msgs.py → omega_msgs.jsonl + rafa_cti_scan.c
ProcessoTipoEntradaSaídaFlags / Notas
omega_json_reconstruct C binário export JSON (ZIP ou raw) omega_objs.jsonl --progress — streaming, sem carregar todo o JSON em memória
omega_extract_msgs.py Python omega_objs.jsonl omega_msgs.jsonl --in_objs <path> --out <path> — extrai mensagens individuais por conversa
rafa_cti_scan.c C streaming arquivo grande / dump binário JSONL append-only + CSV opcional (--csv) Sem descompressão — lê bytes diretamente; campos IC/PP/CV por bloco

Esquema omega_msgs.jsonl — um objeto JSON por linha:

// Cada linha é uma mensagem individual de uma conversa { "conv_i": 42, // índice da conversa (chave primária de busca) "msg_i": 7, // índice da mensagem dentro da conversa "role": "assistant", // "user" | "assistant" | "tool" "model": "gpt-4o", // modelo que gerou a resposta "content": "...", // texto completo da mensagem (campo buscado por omega_search_fast) "ts": 1769000000 // timestamp Unix }

omega_msgs.jsonl é o índice central — omega_search_fast faz busca substring case-insensitive neste campo content. Sem este arquivo, CTI Memory entra em modo "unavailable".

C · Curadoria e Classificação

Omega Forest — 42 Atratores, 5 Caminhos

Classifica cada conversa num dos 5 caminhos de valor usando o vetor [IC_adj, PP_adj, CV] projetado sobre a topologia toroidal de 42 atratores (GF(2⁸), polinômio redutor 0x1D). Gera forest.jsonl — base para navegação e ranking.

omega_metrics_v3.jsonl + omega_conv_stats.jsonl → omega_forest.c → forest.jsonl

42 Atratores: LB_ATTRACTORS = RAF_ATTRACTORS = 42 — conjunto |𝒜| de pontos fixos toroidais. Mapeamento por chunk: omega_point = (hibit + entropy_milli) mod 42. Campo invariante: k_constant = 42 (nunca muda entre chunks). Topologia GF(2⁸) com polinômio redutor 0x1D (0x11D → 1D). Constantes espiral: RAF_SPIRAL_Q16 = 56756, RAF_PHI_Q16 = 105965.

ValorCaminho (enum)Critério de classificaçãoUso no ranking CTI
0 PROCESSUAL Em processamento — IC e PP dentro da faixa média; valor potencial ainda latente Sem bônus
1 VOID Sem sinal de valor detectável — IC e PP abaixo do limiar mínimo Sem bônus
2 FORGOTTEN Valor ignorado/enterrado — IC presente mas acesso histórico muito baixo; não urgente Sem bônus
3 MENOSPREZADO IC alto, PP_adj abaixo de 0.8 — "ouro enterrado"; alta complexidade ainda não explorada Bônus de recuperação: +0.5 no score (recupera conversas de alto IC)
4 URGENT PP_adj > 0.8 — "produto maduro"; padrão de alto retorno imediato pronto para ação Bônus de prioridade: +1 no ranking CTI Memory

Fórmulas de ajuste:

PP_adj = PP × (1.0 − DF)   [DF = decay factor, antiguidade normalizada]
IC_adj = IC / √msgs   [normalizado por volume de mensagens]
node.weight = IC_adj × PP_adj × (1 − decay)

path de ausência: conversas onde nenhuma métrica principal atinge o limiar mínimo — classificadas como VOID (path 1) e preservadas no forest.jsonl com cluster = omega_point mod 42.

Execução: ./omega_forest omega_metrics_v3.jsonl omega_conv_stats.jsonl > forest.jsonl

G · Modelo Conceitual

BitStack World Model — rmrCti/SPEC.md

Ontologia formal que define como matéria, leis e memória se comportam no sistema. Base conceitual do rf_core e da validação por blocos. Arquivo: rmrCti/SPEC.md.

  • Matéria Nibbles e bytes como substrato físico-lógico. Quando organizados formam blocos; blocos formam mundos. A matéria é o único substrato real — tudo o mais é organização sobre ela. Mapeamento ao rf_core: ψ = reset ao estado "matéria limpa" — BitStack com w=0, records=0.
  • Leis (Witness) Regras de validação por bloco. Um bloco só é utilizável quando sua verificação retorna Witness=true. Blocos inválidos são preservados mas não consumidos — análogo ao love_guard=1 do Triad Engine: marcar, não deletar. Mapeamento: χ (leitura) + ρ (transformação) = as leis em ação.
  • Memória Base imutável + overlays/layers equivalentes. Todos os layers seguem o mesmo esquema de blocos. A base nunca é sobrescrita — apenas lida. Implementação: raf_bitstack_state { uint64_t *layers; uint32_t num_layers; size_t bits_per_layer; uint32_t flip_count; uint64_t state_hash; }. Flip = XOR determinístico sobre uma camada; state_hash rastreia a evolução. Mapeamento: Δ (diff) + Σ (acumulação) = a memória crescendo.
  • Testemunha Processo explícito que percorre cada bloco e estampa Witness=true ou false. Análogo a um commit: só o que foi testemunhado entra no fluxo canônico. Mapeamento: Ω = saída testemunhada — o bloco foi validado e seu conteúdo é confiável. Os 42 atratores (omega_point mod 42) identificam a qual "vizinhança toroidal" o bloco pertence após testemunho.

Overlays: camadas adicionais sobre a base imutável. Não resolvem conflitos por merge — cada layer é uma visão independente. A combinação de layers equivale a um diff acumulado, não a uma sobrescrita. Cross-ref com §C: os 42 atratores do BitStack World Model são os mesmos 42 clusters do Omega Forest.

I · Motor de Simulação

Triad Engine — TRIAD / TEXTURE10 / love_guard

Simulação determinística de dinâmica de campo sobre estrutura toroidal (toro). Produz traços CSV consumidos pelo GBS Console. Acoplado ao corpus CTI via triad_cti_couple.py.

run.sh → src/triad_engine.py --steps 300 --seed 42 → out/triad_trace.csv
out.bitstack.jsonl → triad_cti_couple.py → out.coupled.jsonl + out/triad_trace.csv

Definições:

toro
Topologia toroidal — o campo de simulação envolve nas bordas (wrap-around). Cada "step" atualiza todos os pontos do grid com as regras locais de campo
um step
Uma iteração do loop em triad_engine.py: leitura do estado atual, aplicação das regras de campo, atualização de todos os pontos, emissão de uma linha no trace CSV. Com --steps 300: 300 linhas no trace
TRIAD
Algoritmo de acoplamento em triad_cti_couple.py. Para cada registro CTI (campo H / entropy), computa:
· D = D_re + i·D_im — discriminante complexo do estado do campo
· gate_9to1 ∈ {1..9} — gate determinístico (função de H, seed)
· stable_any ∈ {0,1} — flag de ponto fixo
· fr_matches_gate — Fibonacci-Rafael / gate match
· J_n — score local combinado
TEXTURE10
Grid 10×10 bits = 100 bits → packed em 13 bytes (104 bits, 4 bits de padding). Saída: grid10x10_hex (hex string de 26 chars) + paridades: par_row8 (parity por linha), par_col8 (parity por coluna), par_global (global). Serve como "textura de estado" compacta e verificável
love_guard
Flag ética / safety: love_guard = 1 quando X_bad != 0 (anomalia detectada na varredura CTI). Semântica: "preservar, marcar, não forçar colapso". Propagação obrigatória: stage 1 (scan) → stage 2 (TRIAD) → stage 3 (rank / relatório). Invariante verificado em build: assert X_bad != 0 → love_guard == 1
--seed 42
Garante determinismo total — mesma semente + mesmos dados = mesmo trace CSV. 42 = k_constant do sistema (constante toroidal RAFAELIA)

Dialetos CTI aceitos por triad_cti_couple.py: campo "H" ou "entropy" (ambos mapeiam para a mesma entrada do TRIAD). Saída: out.coupled.jsonl + trace para GBS.

K · Integração com llama.cpp

CTI Memory — Recuperação Contextual Durante Inferência

Ponto de convergência de todas as camadas: conecta os artefatos Omega ao motor de inferência LLM, injetando contexto de conversas passadas antes da geração de tokens.

Flag CLIPadrãoFunção
--cti-memory-dirrmrCtidiretório raiz com todos os artefatos omega (omega_msgs.jsonl, forest.jsonl, frames_seed.json)
--cti-memory-search-bin<dir>/omega_search_fastbinário de busca; sem este flag usa fallback interno (scan em processo — mais lento, sem ranking omega)
--cti-memory-forest-path<dir>/forest.jsonlcuradoria omega_forest — carrega mapa conv_i → bônus (URGENT=+1, MENOSPREZADO=+0.5)
--cti-memory-frames-path<dir>/frames_seed.jsontop curado omega_frames_export — bônus curated-top (+1) e tags para cada conv_i presente
--cti-memory-top-k5número de hits a recuperar por query (top-K por score combinado)
--bitstack-log(vazio)path opcional para log de auditoria em formato bitstack JSON (render_event_json)

API interna — namespace cti_memory (common/cti_memory.h):

// common/cti_memory.h namespace cti_memory { struct config { bool enabled = false; // opt-in; default off std::string dir = "rmrCti"; std::string search_bin = ""; // empty → <dir>/omega_search_fast std::string forest_path = ""; // empty → <dir>/forest.jsonl std::string frames_path = ""; // empty → <dir>/frames_seed.json int top_k = 5; }; struct hit { int conv_i = -1; std::string conv_title; int sig_phi = 0; // phi_integral Q16 do snippet (campo [11] NeuroMetrics) int score = 0; // score combinado final }; struct result { bool ok = false; std::string status; // "ok" | "no_hits" | "unavailable" | "error" std::string reason; // ex: "missing_file:rmrCti/omega_msgs.jsonl" }; }

Fórmula de score combinado (ranking interno):

score = base_relevance(query, conv_i)
+ forest_bonus // URGENT=+1, MENOSPREZADO=+0.5, outros=0
+ frames_bonus // +1 se conv_i presente em frames_seed.json
+ phi_weight // sig_phi Q16 normalizado (ética / qualidade do snippet)

Injeção no contexto LLM: os top-K hits são formatados como bloco de contexto inserido no prompt antes da query do usuário — similar a RAG mas com ranking próprio baseado nos artefatos Omega. Fallback interno: quando omega_search_fast está ausente, executa scan linha-a-linha do omega_msgs.jsonl em processo (sem ranking de zona — apenas relevância textual).

# Status de resposta CTI (result.status)
"ok"          busca retornou hits — contexto injetado
"no_hits"    nenhuma correspondência — inferência sem contexto CTI
"unavailable" arquivo ausente — modo degradado silencioso
"error"      ex: missing_file:rmrCti/omega_msgs.jsonl
# result.reason source field
"omega_search_fast" | "scan_fallback" | "none"

Testes em tests/test-cti-memory.cpp: busca com ranking, bônus omega_forest, fallback interno e ausência de arquivos. Comando de ativação: ./llama-server -m model.gguf --cti-memory-dir rmrCti --cti-memory-top-k 5
